# Local HTTPS preview — the easiest and safest way to test Stockroom over HTTPS

This document explains how to run Stockroom over HTTPS **on your own
machine**, with **nothing exposed to the internet**. It's the fastest
way to verify the security hardening actually works before deciding
whether to put the app on Cloudflare.

## What this is

Two Node processes on `localhost`:

```
   browser ──HTTPS──▶ https-proxy.js (port 3443) ──HTTP──▶ server/index.js (port 3000)
                                  │                            │
                                  └── self-signed cert         └── SQLite at data/stock.db
```

Both processes listen on `127.0.0.1` only — never `0.0.0.0`, never
reachable from another machine on your LAN, never reachable from the
internet. There's no Cloudflare account, no DNS change, no port
forwarding, no public IP involved.

The browser will warn that the cert is "not trusted" on first
visit. That's expected and fine — it's a self-signed cert for
localhost. Click **Advanced → Proceed to localhost (unsafe)** once
per browser.

## What this proves

Running this lets you verify in the browser:

- The app actually loads over `https://localhost:3443/`.
- The auth cookie is set with the `Secure` flag, so it only travels
  over HTTPS (curl confirms this — see "Verify" below).
- HSTS is active: `Strict-Transport-Security: max-age=31536000; includeSubDomains`.
- CSP / X-Frame-Options / X-Content-Type-Options headers are all
  present (visible in DevTools → Network → click any request).
- The rate limiter blocks brute-force attempts (try 6 wrong
  passwords in a minute — the 6th gets HTTP 429).

None of these would behave correctly over plain `http://`. With this
proxy you get a realistic preview of production behaviour without
any internet exposure.

## Files in this setup

- `data/localhost.crt`, `data/localhost.key` — the self-signed cert
  and key. Generated by `openssl` (see step 1). **Already present in
  this repo** so you don't have to regenerate.
- `server/https-proxy.js` — the proxy. ~100 lines, no deps.
- `server/index.js` — the existing app, unchanged. You run this on
  port 3000 with `SM_ALLOW_INSECURE_SECRET=1` for local dev (or a
  real `JWT_SECRET` for production-like behaviour).

The proxy is excluded from `.gitignore`? No — actually we **want** it
checked in so anyone cloning the repo can run this immediately. The
cert+key are local-only artifacts (they're not sensitive — a
self-signed cert for `localhost` proves nothing about identity), but
if you'd rather regenerate them on each clone, see step 1.

## Step-by-step

### 1. (One time) Generate the self-signed cert

Already done in this repo — `data/localhost.crt` and
`data/localhost.key` are present. If you ever need to regenerate:

```bash
cd C:/Users/yovre/stock-manager
openssl req -x509 -newkey rsa:2048 -nodes -sha256 -days 3650 \
  -keyout data/localhost.key -out data/localhost.crt \
  -subj "/CN=localhost" \
  -addext "subjectAltName=DNS:localhost,IP:127.0.0.1"
```

10 seconds. Valid 10 years. Only `CN=localhost` + `127.0.0.1`, no
other names. Useless to anyone outside this machine.

### 2. Start the app (port 3000, plaintext)

```bash
cd C:/Users/yovre/stock-manager
SM_ALLOW_INSECURE_SECRET=1 node server/index.js
```

You should see:

```
[ok] stock-manager listening on http://localhost:3000
[ok] default login -> admin / admin123
```

(The dev-mode secret is fine here because nothing leaves your
machine. For Cloudflare, set a real `JWT_SECRET`.)

### 3. Start the HTTPS proxy (port 3443)

Open a **second terminal** in the same folder:

```bash
cd C:/Users/yovre/stock-manager
node server/https-proxy.js
```

You should see:

```
==================================================================
[proxy] HTTPS preview listening on https://localhost:3443
        Forwarding plaintext to http://127.0.0.1:3000

        Open:  https://localhost:3443/
        Note: browser will show a cert warning (self-signed).
        Click "Advanced" → "Proceed to localhost" to continue.

        Stop with Ctrl-C.
==================================================================
```

### 4. Open in your browser

Visit `https://localhost:3443/`. Your browser will say:

> Your connection is not private
> NET::ERR_CERT_AUTHORITY_INVALID

That's the self-signed cert being unknown. Click **Advanced**, then
**Proceed to localhost (unsafe)**. The app loads.

Sign in with `admin / admin123`. Open DevTools → Network → click
`/api/auth/login` in the response list → look at the `Set-Cookie`
header. You should see:

```
sm_token=...; Max-Age=28800; Path=/; Expires=...; HttpOnly; Secure; SameSite=Lax
```

Note the `Secure` flag — only sent over HTTPS, won't leak if a
misconfigured proxy downgrades to HTTP.

### 5. Verify from a phone (optional)

The proxy only listens on `127.0.0.1`, so it's **not** reachable from
your phone. That's by design. To test from your phone, you'd need
to either:

- Bind the proxy to `0.0.0.0` (don't, except for a quick test on a
  trusted LAN), or
- Use Cloudflare Tunnel (see `CLOUDFLARE.md`) for a real public URL.

For now, the desktop browser preview is enough.

## Verify the hardening (curl)

```bash
# App reachable via HTTPS through the proxy:
curl -sk https://localhost:3443/ -o /dev/null -w "HTTP %{http_code}\n"

# All security headers should be present:
curl -sk -D - https://localhost:3443/api/stats/summary \
  -H "Authorization: Bearer x" -o /dev/null \
  | grep -iE "^(content-security|strict-transport|x-frame|cache-control|referrer-policy)"

# Login sets the Secure cookie:
curl -sk -X POST https://localhost:3443/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"admin123"}' \
  -D - -o /dev/null | grep -iE "^set-cookie"

# Rate limiter blocks brute force (6th attempt returns 429):
for i in 1 2 3 4 5 6; do
  curl -sk -o /dev/null -w "attempt $i: %{http_code}\n" \
    -X POST https://localhost:3443/api/auth/login \
    -H "Content-Type: application/json" \
    -d '{"username":"admin","password":"wrong"}'
done

# Plain HTTP also works (the app serves both ports, but only
# behind HTTPS does the secure cookie + HSTS kick in):
curl -s http://localhost:3000/ -o /dev/null -w "HTTP via http: %{http_code}\n"
```

## When you're done

Stop both Node processes with Ctrl-C. The cert and key stay on disk
in `data/` for next time.

If you decide you want to go to Cloudflare next, the proxy becomes
useless and the production guidance in `CLOUDFLARE.md` applies.

## Why this is the safest option

- **No internet exposure** — proxy binds to `127.0.0.1` only.
- **No account, no DNS, no billing** — purely local.
- **No real credentials** — the proxy uses a self-signed cert that
  proves nothing about identity. If your laptop is compromised,
  the attacker can already run things on your machine — the cert
  doesn't help them.
- **No persistent state** — nothing is written outside `data/`. Stop
  the processes and you've reverted.
- **Reversible** — `git checkout -- data/localhost.{crt,key}` (or
  just delete them) and the proxy refuses to start.
